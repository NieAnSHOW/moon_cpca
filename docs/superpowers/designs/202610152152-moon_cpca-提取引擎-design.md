## 1. 用户当前理解（认知校准结果）

来自 G1-Anchor 确认：本单元的本质是「**跨实现对账**」而不是「重写一个解析器」。验收判据不是算法是否优雅，而是 MoonBit 版与 Python cpca v0.5.5 在同一输入上逐字段一致——包括上游的 quirks（同名区默认取候选列表首元素、`addr` 吞后续文本、pos 的码点索引口径）。因此设计上真正要裁决的是三件事：(a) 用什么匹配承载结构，使「全称/简称共享候选 + 重叠时去重」与上游 Aho-Corasick 的 `iter` 行为等价；(b) 位置口径怎么锁定为可断言的单一形态（上游码点索引 = MoonBit 字符序号，UTF-16 码元口径禁用）；(c) golden 集作为「等价」的唯一基准如何生成、锁版本、防脱钩。

## 3. 关键约束（技术 / 成本 / 合规）

### 3.1 技术约束

1. **行为等价优先于结构同构**：上游用 `pyahocorasick`，MoonBit 生态无等价包且零依赖要求禁止引第三方——所以结构不必同构，但**可观察行为必须同构**（D1 裁决）。这一约束直接推出「承载结构自建 + golden 逐字段对账」的路线。
2. **同名区候选顺序即数据行序**：上游 `add_addr_info`（`matcher.py:58-60`）同名追加，故「朝阳区」→ `[220104, 110105]`（PRD F2-3）。候选顺序是行为的一部分，引擎侧不得对同名候选重排序。
3. **字符串索引语义**：上游 pos 为 Python str 索引 = 码点索引（非 BMP 字符占 1 位，PRD F2-9 实测 `index=4`/`len=10`）；MoonBit `String::char_length()` 为字符长度（= 10，与上游同口径）、`length()` 为 UTF-16 码元长度（= 11，`F:/Temp/posprobe/posprobe_test.mbt:2-3` 实测）。引擎 pos 必须锁定 Char 迭代口径并对 `length()` 禁用。
4. **平台目标**：native 可用、wasm/js 本机不可用（`probe/PROBE.md` §2 目标可用性矩阵），已登记 `[LOCAL_DEAD_LINK]`。

### 3.2 平台接缝与目标分叉（PS1-PS3 / TB1-TB3）

**PS1 分叉能力登记**：

| 能力 | 分叉轴 | 接缝层位置 |
|------|--------|-----------|
| pos 索引口径 | native/wasm 下 `String` 内部表示是否一致 | 引擎内部单一换算函数（`pos_of`） |
| 构建与测试目标 | native（可用）vs wasm/js（本机不可用） | `moon.mod` 的 `preferred_target` + CI 矩阵（与数据单元同一约定） |

**PS2 接缝收编**：pos 口径的全部分歧收进引擎内部一个换算点，调用方只见「字符序号 + -1」；无任何调用侧分支。目标分叉只存在于 `moon.mod` 与 CI，引擎源码零目标条件编译。

**PS3 一致性对照**：greenfield 无既有接缝；目标声明与数据单元保持一致（兄弟 PRD 兼容性 NFR 同一口径），避免双口径。

**TB1-TB3**：pos 换算为纯函数，无平台分支；目标选择由工具链处理而非被测代码。`N/A — no platform branches in engine code.`

### 3.3 渲染接缝（RS1-RS4）

`N/A — no UI, no render-surface assertions.` 引擎是纯函数库，无界面产物。

### 3.4 成本约束

- golden 由上游 oracle 现生成：上游仓库 vendored 在本地（`chinese_province_city_area_mapper/`），生成命令是「一次 Python 调用」，无需网络、无需人工抄写 30+ 条期望值。
- 单条 ≤ 5 ms、golden 全量 ≤ 30 s（PRD NFR 性能行）——自建匹配结构的真正代价在这里，成为 D-07 的度量依据。

### 3.5 合规约束

- 引擎零网络/文件/环境变量（PRD NFR 安全性，机检命中数 = 0），输入文本不出进程。
- README 注明上游出处与 MIT（PRD FR-21 同源纪律，与 PRD 数据表侧 FR-08 对齐）。

## 6. 设计决策追溯表

| 设计决策 | which/why 论证要点 | 回链 PRD 条目 | 代价（被弃项牺牲了什么） | 复开条件 |
|----------|--------------------|---------------|--------------------------|----------|
| **D-07 匹配承载结构：省/市/区三级 Map 索引 + 按目标长度降序的候选词枚举（最长匹配语义），不实现 Aho-Corasick** | 备选 A：复刻 Aho-Corasick（goto/fail/output 三表）——否决理由：上游的可观察行为等价只需要「(1) 全称与简称共享同一候选列表，(2) 同一区间内最长匹配胜出，(3) 全称/简称重叠时只 yield 一次」三条；aho 的 fail 跳转与 output 链是为「多模式一次扫描」的最优性服务，而零依赖要求下自建 AC 的代码量与 bug 面都远超收益。备选 B：纯枚举所有候选词 × 输入子串（暴力）——否决：3511 条候选 × 输入长度的平方复杂度，PRD NFR 5 ms 行会被击穿；用「按候选词长度降序 + 从每个起点找最长命中」可用 Map 索引把比较次数降到「候选词表规模 × 起点数」以内的可接受量级。选定：以地名为键的 Map（同名 → 候选列表），匹配时从每个字符起点尝试由长到短的窗，首个命中即该起点的最长匹配 | FR-01、FR-04、FR-07、FR-08、NFR 性能行 | 放弃了 aho 的单次扫描最优性（长输入上多花常数倍时间）；换来实现体积小、行为可用 golden 直接对账 | golden 回归实测单条 > 5 ms 或全量 > 30 s（PRD NFR 性能行被击穿） |
| **D-08 greedy 语义按上游 `iter` 复刻：匹配区间不重叠、全称与简称共享候选且重叠去重** | 上游 `matcher.py:74-92` 的三条规则：(a) `end_index <= prev_end_index` 跳过（区间不重叠）；(b) 简称与全称共享同一 attr 列表（`_first_add_addr` 返回同一 `share_list`）；(c) `start_index == prev_start_index` 时同区间两个匹配只保留后者并清空 prev。复刻这三条即可让「上海市」只 yield 一次、且拿到完整候选列表 | FR-01、FR-08、FR-09、FR-13 | 需为 (c) 的「后写胜出 + 清空」写专门覆盖用例；这是上游的特性而非通用最优语义，但它就是等价基准 | 上游改变 `iter` 去重规则（PRD 10.5 假设行） |
| **D-09 pos 口径 = 字符序号（`char_length` 语义，代理对算 1 个位置；与上游 Python 码点索引同口径）** | 实测澄清（reviewer 回执后复跑）：上游 Python 3 str 索引即**码点索引**（`'上海😀市徐汇区虹漕路'.index('徐汇区') = 4`、`len = 10`），与 MoonBit `char_length()` 完全同值；UTF-16 码元口径（`length() = 11`）才是唯一不可用口径。故不存在「码元 vs 字符差 1」的两语义鸿沟——原本的备选 A 论证前提被实测推翻。仍选字符序号（按 Char 迭代计数）：MoonBit 所有字符遍历基于 Char，用 `length()` 需额外换算且把内部表示泄漏进契约。golden 集中放含 😀 的用例（上游 pos = 4 / MoonBit char 序号 = 4）作为口径锚 | FR-10、FR-11、NFR 兼容性行 | 无换算代价（两口径同值）；放弃「更贴近上游实现细节」的码元形态 | golden 用例实测出现非 BMP 输入 pos 不一致，或上游改用非码点口径 |
| **D-10 golden 生成器与数据生成器同源：一条 Python 命令产出「输入 → 上游输出」用例集文件（JSONL，每行一个用例），带上游版本标识** | 备选 A：手写期望值——否决：30+ 条 × 8 字段的手工抄写必然出错且不可复现。备选 B：MoonBit 侧实现反向断言上游——否决：循环论证（用被测逻辑定义期望）。选定：oracle 现生成（`transform(..., pos_sensitive=True[, umap])`）；文件形态 = `testdata/golden.jsonl`（spec §4.4 锁定），上游版本标识**逐行**冗余写入（JSONL 无注释文件头） | FR-14、FR-15、FR-16、G-04 | golden 生成依赖 Python 环境（与数据单元同一代价，共担） | 上游仓库不再随本仓库 vendored，或需在 CI 无 Python 环境生成 |
| **D-11 golden 与上游版本绑定：每行记录 `upstream_version` 字段，引擎测试入口断言全部行一致** | 备选：只写 README——否决：README 与测试种子可脱钩，种子被单独复制到别处时基准丢失。逐行冗余 + 测试入口断言，使「拿旧种子跑新上游」变成显式失败 | FR-14、FR-15 | 测试入口多一次断言（可忽略成本） | 上游版本号不可机读（当前 `__init__.py:9` 可读） |
| **D-12 同名候选列表构造顺序 = 数据表行序，引擎侧零排序** | 上游同名追加语义（PRD F2-3）决定「取首元素」的结果；若引擎侧按 adcode 排序，「朝阳区」默认会从 220104 翻成 110105，与上游分叉 | FR-08、FR-09、G-03 | 引擎放弃「稳定排序带来的确定性外观」；确定性改由数据行序提供（数据单元 FR-12 保证行序 = 上游） | 上游改变 `add_addr_info` 追加语义 |

## 7. 降级路径 + 数据流方向

**FE1 降级路径**：引擎有两条需要成路的路径——**主路径**（地名命中 → 结构化输出）与**无命中路径**（输入无可匹配地名 → 全无值记录，PRD FR-12 / F2-8）。二者不是「主/降级」关系而是两个互斥输入域，可观察契约都已定义（主路径输出三级 + adcode + pos；无命中输出全 None + pos 全 -1）。判定：`无降级路径——不存在主路径不可用时切换到替代实现的形态；「无命中」是输入域分支而非降级，其契约由 PRD FR-12 显式定义。`

**FE3 外部依赖前置条件**：主路径无外部硬依赖（零网络/文件/环境变量，PRD NFR 安全性）。数据表是编译期常量（随包分发），不是运行时外部依赖。`N/A — no external hard dependency.`

**DF3 数据流方向**：`N/A — no sensitive data flow.`（PRD 10.7 已裁「无」；输入文本不进任何持久化或外传通道，机检判据见 PRD NFR 安全性行。）

## 10. 外部契约真值源（SD1-SD2）

`N/A — no internal external-bridging contract.` 需要说明的一点：引擎调用的「外部契约」是**上游 Python 实现的可观察行为**，其真值源 = 上游源码 + 本机 oracle 实跑输出。该真值源在 PRD 的 F2 表已逐条登记命令与结果（`F:/moonbit比赛/moon_cpca/chinese_province_city_area_mapper/cpca/__init__.py` 与 `matcher.py` 的 `file:line` + 可重跑 python 命令），不属「宿主运行时注入 / 原生桥 / 平台注入 API」类别，故无 SoT 二选一决策；但等价基准（DC3）在此锁定：**等价 = 与上游实跑输出逐字段相等，锚定上游源码可观察行为 `file:line`**。
