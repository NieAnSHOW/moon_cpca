# moon_cpca 区划数据表 Implementation Plan

## Goal
把上游 `chinese_province_city_area_mapper/cpca/resources/adcodes.csv`（3511 条区划记录）转换为 MoonBit 编译期常量数据产物 `data/adcodes.mbt`（含 `adcodes` 数组与 `Level` 枚举），交付可复现生成脚本、内置自校、机检脚本与 README 数据来源说明，使「入库数据 = 上游 CSV」成为一条可重跑命令的结论。

## Architecture
单向数据链路：上游 CSV（vendored，只读）→ `tools/gen_adcodes.py`（唯一权威生成入口：读 CSV、派生 level、写 `.mbt` 产物与 `data/moon.pkg`、内置自校、输出报告）→ `data/adcodes.mbt` 编译期常量 → 被兄弟单元（提取引擎）以 `import { "<module>/data" @adcodes }` 消费。自校为生成命令的内置步骤（成功即蕴含自校通过，失败 = 非零退出 + 报告落盘），不设独立校验路径。产物永不由手工编辑（生成目录所有权见 spec §8）。

## Tech Stack
- MoonBit 工具链：`moon 0.1.20261012 (748b63c 2026-10-12)`（仓库实测：`moon version`；证据 `probe/PROBE.md` §1 本机工具链事实）
- 构建目标：native（`moon.mod` 置 `preferred_target = "native"`；spec §9.2 登记 wasm/js 为 `[LOCAL_DEAD_LINK]`）
- 生成器与机检脚本语言：Python 3.12.10（仓库实测 `python --version`；上游 json/csv 标准库，零第三方）
- 上游参考实现（只读基准，不修改）：Python cpca v0.5.5（`chinese_province_city_area_mapper/cpca/__init__.py:9` `VERSION = (0, 5, 5)`）
- 数据源：`chinese_province_city_area_mapper/cpca/resources/adcodes.csv`

> 溯源规则: 每项库名/版本必须溯源 spec 章节号或仓库实际依赖（如 grep 依赖清单文件中依赖项的实际版本），禁止凭记忆填写（如拼错库名、捏造不存在的依赖）。
> 溯源结果: MoonBit 版本 → 仓库实测 `moon version`（`probe/PROBE.md` §1）；Python 版本 → 仓库实测 `python --version`；cpca 版本 → `chinese_province_city_area_mapper/cpca/__init__.py:9`。本计划不引入任何第三方库（spec §4.3「无网络请求」「零运行时依赖」）。

## Global Constraints
- 零运行时依赖：产物只依赖 `moonbitlang/core`（spec §4.2、PRD NFR 兼容性行）
- 数据载体 = 编译期常量，禁运行时读文件（PRD G-01/D5 裁决）
- 产物与上游 CSV 逐字段一致、行序一致（spec §4.4 自校契约）
- 来源标识只含输入决定字段（上游文件名 + 记录数 + CSV 内容 sha256），**禁墙钟时间戳**（spec §4.3；否则 A2「重生成 diff = 0」不可达）
- 产物不含经纬度字段（spec §4.4 无经纬度字段项；PRD FR-11）
- 生成器零网络（spec §4.3；PRD US-01 验收标准 3）
- 自校失败 = 非零退出，不产出有效产物（spec §4.3 退出语义）
- 生成目录所有权：`data/adcodes.mbt` 全量重建、禁手工编辑（spec §8 GO1-GO3）

- **缺陷频率未知说明**：本 plan 为新实现（非缺陷修复类计划），修复轮按需触发。**连续复验次数 N 声明**：任一缺陷关闭前，须在真实目标环境（本机 native 目标）**连续 N = 3 次**复验全部通过，逐次附证据（复验时间 + 环境标识 `native / moon 0.1.20261012` + 结果输出）；单次通过不关闭；中途一次失败计数归零，间歇性缺陷按未愈处理并升级运行时取证（R1/R8）。
- **R1 实证升级**：同一缺陷修复两轮未愈，第三轮起**禁止推断式修复**，必须升级到运行时取证（真实运行产物 dump / 生成器中间态检查 / CSV 与产物逐字节对账），取证产物附入修复轮报告。
- **R2 类灭绝**：发现缺陷类 X（如「派生规则写错」「行序被排序」「报告缺明细」）时，本轮完成定义 = 全仓按缺陷模式检索同类（检索式覆盖：生成器全部分支 / 自校全部检查项 / 机检脚本全部子开关）并逐个处置或显式豁免；只修报告实例不放行。**新缺陷类灭绝时同步扩充本 plan 的静态门检索式（衔接 Slice Checkpoint S1）**。
- **R3 根因追问**：修复轮报告须标注修复性质（`根因修复` / `症状修复`）；标为症状修复时必须登记根因假设与后续验证计划，交决策层裁决。
- **R4 取证先行**：任何失败处置第一步 = 取证落档（失败命令 + 退出码 + stderr 原文 + 报告文件内容 + 产物相关片段），禁止先改代码。

- **R7 调试环还原**：定位用临时调试构件（临时 print / 调试开关 / 临时脚本）必须移除，经还原后的终版构建复验通过才算修复完成。
