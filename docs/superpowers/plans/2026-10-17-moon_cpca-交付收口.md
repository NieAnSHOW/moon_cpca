# moon_cpca 交付收口 Implementation Plan

## Goal
在不改变引擎算法语义的前提下，使 moon_cpca 仓库可按交付收口 PRD 完成干净 clone 复现、mooncakes v0.1.0 发布、native/wasm-gc 可验证、上游用例逐条对齐，以及 README/example/诊断报告可执行。

## Architecture
以 `tools/regen.py` 为唯一权威再生入口：裸生成器产出 raw 文件，wrapper 负责包级格式化、更新后的 `check_artifact.py`、golden 自检与 `git diff`。交付面按四个批次推进：Batch 0 完成 gate 基础（快照、依赖、checker、regen、coverage、fmt），Batch 1 完成改名与可复现，Batch 2 完成 CI 与包体，Batch 3 完成发布与终验。Batch 0 通过前不进入 feature batch。

## Tech Stack
- MoonBit 工具链 `0.1.20261012`（`moon version`；spec §1.2 F-01/F-05）
- Python `3.12.10`（`python --version`；spec §1.2 F-15）
- pandas `2.3.1`、pyahocorasick `2.3.1`、setuptools `80.9.0`（spec §3.1；本机 `python -c "import pandas, ahocorasick, pkg_resources"` 已验证）
- 运行时零第三方依赖（`moon.mod` deps 空；`tools/check_deps.py`；spec §3.1/§3.2）
- Python 工具仅用标准库（`tools/*.py`；spec §3.3/§3.4/§3.5）

## Global Constraints
- `moon publish --dry-run` 成功判据 = 输出 `Server status: 202 Accepted` + `Dry run completed successfully` 且无 manifest error；exit 255 不单独判失败（spec §3.1）。
- 真实发布成功 = `Server status: 200 OK`（spec §3.1/A-05）。
- Vendored 快照逐字 8 路径，含 `cpca/resources/__init__.py`，不含 `drawer.py`（spec §3.2/M-03/A-19）。
- `moon fmt --check` 覆盖 `engine/`、`testdata/`、`moon.mod`、`moon.pkg`（spec §1.2 F-07/§3.6）。
- `check_artifact.py` 同时接受 raw 与 formatted 记录行；malformed 是已知违规（spec §3.4）。
- `check_coverage.py` 必须解析 14 行，row 14 固定值见 spec §3.5；不得静默跳过未知 ID。
- 单份 PRD/spec；不拆分（PRD §10.6；spec Step 0）。
- 无 feature batch 早于 Batch 0；Batch 0 通过后 spec re-freeze（spec §6/§8.1.1/§13）。
- 所有命令使用仓库相对路径；不引入机器绑定绝对路径（spec §12 EX-01/EX-02）。
- 不升级依赖；不新增运行时依赖（spec §3.1/§3.7）。
