## 一、问题陈述

> 本单元解决的问题：把一段任意中文文本中的省/市/区三级行政区划提取为结构化结果，**行为与上游 Python cpca v0.5.5 可观察一致**。
>
> 现状痛点是「MoonBit 生态没有可用的区划解析库」（申报书已查重：mooncakes.io 上 address 类包 mooncidr/mbt-email/moonloom/bech32-kit 分别是 IP/邮箱/内容寻址/SegWit 地址，awesome-moonbit、GitHub topic:moonbit、moonbitlang/core 均无中文行政区划解析项目）。做订单分析、用户画像、日志地理归因的 MoonBit 使用者，目前只能把地址当纯文本，或用正则硬编码——「浙江杭州余杭区文一西路 969 号」「杭州余杭梦想小镇」「余杭区……」三类输入无法归一。

## 二、目标

| 目标编号 | 目标描述 | 衡量指标 | 目标值 | 当前值 | 衡量时间 |
|----------|----------|----------|--------|--------|----------|
| G-01 | MoonBit 侧单条地址提取结果与上游 Python cpca v0.5.5 逐字段一致（省/市/区/地址/adcode + pos 三项） | 在固定输入集合上两版实现输出不一致的字段数 | 0 个字段不一致 | 当前无 MoonBit 实现（不可比） | 引擎单元验收时 |
| G-02 | 简称/别名归一与缺省层级补全能力与上游同语义 | 简称类输入（省/市/区各级）解析结果 adcode 与上游一致的比例 | 100%（见 F2-12 口径） | 当前无 | 引擎单元验收时 |
| G-03 | 同名区在无上级限定时取 attr_infos[0]，有上级限定时按归属前缀消歧 | 「朝阳区」类同名区在两种限定下的结果 | 均与上游一致（F2-3、F2-11） | 当前无 | 引擎单元验收时 |
| G-04 | 交叉验证用例集由上游实跑生成、随仓库提交，可重跑复现 | golden 集覆盖三类输入（完整地址/仅区县/简称+数字混排）且每条含上游实跑输出 | ≥ 30 条且全部由 oracle 生成 | 当前无 | 引擎单元交付时 |

## 三、非目标

| 非目标 | 排除原因 |
|--------|----------|
| 街道/门牌号级解析 | 申报书明确不做（无权威数据源、误差不可控），上游 cpca 亦不做 |
| 经纬度与逆地理编码 | 属 geocoding 语义域，申报书明确不做 |
| 区划数据在线更新服务 | 数据随包版本化发布即可满足（申报书）；数据生成属兄弟 PRD |
| pandas DataFrame 返回形态 | 上游默认返回 DataFrame（隐式依赖 pandas），MoonBit 版返回原生 struct；申报书「明确不做/差异说明」已裁定 |
| 多地址长文本的批量提取 API（`transform_text_with_addrs`） | 申报书只列单条 `extract`；上游该能力作为 `[EXT]` 由本单元 P2 承载，不进 P0 |
| 搜索引擎式模糊匹配（编辑距离/拼音） | 上游未提供，属新能力；申报书范围外 |
| 修正上游 quirks（如 umap 文档与实现差异、addr 吞后续文本） | 裁决 D2：移植基准是「可观察行为对齐」，修正行为会使两版实现分叉，超出移植范围 |

## 四、用户故事

```
用户角色：MoonBit 库消费者（订单清洗/日志归因/表单联动）、移植验收者
```

### US-01【P0】消费者提取单条地址的三级行政区划

作为 MoonBit 库消费者，我想要输入一段中文地址文本得到省/市/区结构化结果，以便把自由文本地址归一为可统计字段。

验收标准：
1. 对含完整省市区地址的输入，返回省、市、区三级名称及 adcode，且与上游实跑输出逐字段一致（Yes/No）。
2. 对输入「徐汇区虹漕路461号58号楼5楼」（缺省），返回省=上海市、市=市辖区、区=徐汇区、adcode=310104（Yes/No，对应 F2-5）。
3. 对输入「江苏省淮安市清江浦区人民路111号」，返回 addr 字段 = `人民路111号`（Yes/No）。
4. 缺失层级以「无值」表示（非空字符串、非占位文本，Yes/No）。

### US-02【P0】消费者处理简称与混排输入

作为 MoonBit 库消费者，我想要简称（「江苏」「淮安」「内蒙古」「宁夏」）也能解析，以便应对手填地址的常见省略写法。

验收标准：
1. 输入「江苏」→ 省=江苏省、adcode=320000（Yes/No，F2-12）。
2. 输入「淮安」→ 省=江苏省、市=淮安市、adcode=320800（Yes/No，F2-12）。
3. 输入「内蒙古自治区」→ 省=内蒙古自治区、adcode=150000；输入「宁夏」→ 省=宁夏回族自治区、adcode=640000（Yes/No，F2-12）。
4. 数字字母混排（如「abc江苏xyz淮安清江浦区人民路111号」）不产生误匹配，结果与纯中文输入口径一致（Yes/No）。

### US-03【P0】消费者依赖位置信息排查误匹配

作为 MoonBit 库消费者，我想要拿到省/市/区各自在原文中的位置，以便在解析结果可疑时快速回看原文片段。

验收标准：
1. 位置值口径为「字符序号」（第 N 个字符，从 0 起），未匹配层级为 -1（Yes/No）。
2. 输入「A1上海市徐汇区」→ 省_pos=2、区_pos=5（Yes/No，oracle 实跑值）。
3. 位置值在含非 BMP 字符的输入上与上游口径一致：`'上海😀市徐汇区虹漕路'` 的区_pos = 4（Yes/No，F2-9 + F2-10）。

### US-04【P0】验收者确认 MoonBit 与上游行为对齐

作为移植验收者，我想要一套由上游实跑生成、可重跑的对照用例集，以便在每次数据更新或引擎改动后立刻发现行为分叉。

验收标准：
1. 用例集中每条输入都带上游实跑输出（省/市/区/地址/adcode + pos），并记录生成该输出的上游版本标识（Yes/No）。
2. 用例集规模 ≥ 30 条，覆盖：完整省市区地址、仅区县、仅市、仅省、简称、数字字母混排、无匹配输入、空输入（Yes/No，可按覆盖类别计数）。
3. 用例集可由一条命令从上游仓库重新生成，且重新生成结果与仓库内版本 diff 为 0 字节（Yes/No）。

### US-05【P1】消费者处理同名区

作为 MoonBit 库消费者，我想要同名区（如北京朝阳区 / 长春朝阳区）有确定性行为，以便下游统计不因同名产生随机归属。

验收标准：
1. 无上级限定时取候选列表第 0 个：「朝阳区汉庭酒店大山子店」→ 吉林省/长春市/朝阳区/220104（Yes/No，F2-3、F2-4）。
2. 有上级限定时按归属前缀消歧：「吉林省朝阳区不知道店」→ 吉林省/长春市/朝阳区/220104；「福建省鼓楼区鼓楼医院」→ 福建省/福州市/鼓楼区/350102（Yes/No，F2-11）。
3. 同名区在同一次会话内对同一输入返回同一结果（可重复，Yes/No）。

### US-06【P2】消费者使用区名消歧提示参数

作为 MoonBit 库消费者，我想要用 umap 参数指定同名区的具体 adcode，以便在业务已知区划时固定结果。

验收标准：
1. `umap={"朝阳区":"110105"}` 时「朝阳区汉庭酒店大山子店」→ 北京市/市辖区/朝阳区/110105（Yes/No，F2-4）。
2. umap 键为区名、值为 6 位 adcode 字符串；未命中 umap 的输入行为与不传 umap 一致（Yes/No）。
3. umap 传入未知区名不改变其他输入结果（Yes/No）。

> - 对象「候选列表」× FR-07 × FR-08：上级限定时归 FR-07（归属前缀消歧），无上级限定时归 FR-08（取首元素）；两种态互斥且各自可 Yes/No 判定。

### 10.6 PRD 拆分声明

**为什么拆**：moon_cpca 需求覆盖「数据表」与「匹配引擎」两个可独立交付、独立测试的子系统（触发条件 1；触发条件 4：上游实现 426 行 + 3511 条数据 + MoonBit 引擎 + golden 测试超出单个 AI 上下文窗口可完成范围）。按独立可展示交付物纵切为两份。

| 归属 | 覆盖单元 | 共享接口/边界（与兄弟 PRD 对齐） | spec 承接 |
|------|----------|----------------------------------|-----------|
| 本 PRD 为拆分之一（共 2 份） | 提取引擎单元：匹配语义 + extract API + pos/umap + golden 对照 + README/CI | ① 只消费兄弟 PRD 的区划数据表产物，不自带第二份数据源；② 依赖的数据字段为 adcode/name/排列顺序（兄弟 PRD FR-02/FR-10/FR-12）；③ 重名多记录并存形态是 FR-08/FR-09 的前提（兄弟 PRD FR-10） | 单个 spec：`[time]-moon_cpca-提取引擎-spec.md` |
| 兄弟 PRD | 区划数据表单元：上游 CSV → 可复现生成的 MoonBit 数据产物 | 同上（镜像登记） | 单个 spec：`[time]-moon_cpca-区划数据表-spec.md` |

**单单元验收可达性验证结论**：
- 本 PRD（提取引擎单元）：**可达**。只完成本单元（兄弟单元未交付）时，G-01..G-04 与 FR-01..FR-21 均可独立观察——引擎用兄弟单元已登记的数据契约为输入（静态数据文件），golden 集由上游 oracle 现生成，不依赖兄弟单元的生成脚本已交付。
- 兄弟 PRD（区划数据表单元）：**可达**（见其 10.6，口径一致）。
