### 3.3 权威再生入口 `tools/regen.py`

**唯一权威**：`tools/regen.py`。裸 `gen_adcodes.py` / `gen_golden.py` 是下层入口，不承担逐字节契约。

CLI：

| 参数 | 语义 |
|------|------|
| 无参数 | 完整再生：生成 + 格式化 + 检查 + diff |
| `--no-network-check` | **wrapper 级**零网络审计：wrapper 对两个生成器子进程（`gen_adcodes.py` 与 `gen_golden.py`）统一建立 PEP 578 审计钩子或等价 guard；报告总事件数 = 0。仅保护数据生成器不满足契约 |
| `--verbose` | 输出每步命令与耗时到 stdout |
| `--skip-fmt` | **不提供**。跳过格式化会违反 FR-10；不接受以调试名义绕过验收 |

固定顺序（每一步失败即停止）：

1. `python tools/gen_adcodes.py`（raw，自检 6/6；网络事件纳入 wrapper 总计）
2. `moon fmt data/`（包级格式化，接受 formatter 尾逗号）
3. `python tools/check_artifact.py --records --fields --levels --order --dup`
4. `python tools/gen_golden.py`（raw；网络事件纳入 wrapper 总计）
5. `moon fmt testdata/`
6. `python tools/check_golden.py`
7. `git diff --exit-code`
8. `git status --short`（输出必须为空；`_build/` 为 gitignored，不在此输出出现；如需检查 ignored，另跑 `git status --short --ignored`）

**网络证据**：`--no-network-check` 成功时写 `_build/regen_network.json`，字段 `generators` = `["gen_adcodes","gen_golden"]`、`events` = 0；任一事件 > 0 时退出 2，stderr 列出事件类型与生成器名，并写 `_build/regen.log`。只保护 `gen_adcodes.py` 时 `generators` 不完整，契约失败。

**传播机制**（PEP 578 钩子不跨 `subprocess` 继承）：首选 wrapper 用 `runpy` 在同一进程内依次执行两个生成器，整个序列在同一个 `sys.addaudithook` 下；备选为两个子进程注入临时 `sitecustomize.py` 到 `PYTHONPATH`。`gen_golden.py` 本身无 `--no-network-check`，不得把 flag 只传给数据生成器。T2 样本：临时副本 `gen_golden.py` 插入 `socket.socket()`，运行 wrapper 必须 exit 2 且 `regen_network.json` 的 `events` > 0。

退出码：

| 退出码 | 含义 | 证据通道 |
|--------|------|----------|
| 0 | 全部步骤成功且工作树干净 | stdout 摘要 + `_build/regen.log` |
| 2 | 生成或检查失败（缺 CSV、缺 oracle 依赖、checker/golden 不一致） | stderr 具名步骤 + `_build/gen_report.json` + `_build/regen.log` |
| 3 | 格式化失败（`moon fmt` 非 0） | stderr formatter 输出 + `_build/regen.log` |
| 4 | 工作树不干净或 diff 非 0 | `git status --short` / `git diff` 原文 + `_build/regen.log` |

stdout/stderr 契约：

- stdout：每步一行 `STEP <n> <name> <exit>` + 最终 `REGEN OK` / `REGEN FAIL`。
- stderr：失败步骤名、原命令、退出码、首个错误行；不把整段日志只写 stderr。
- 超时：单步 600 s；整条 wrapper 1800 s；超时退出 2，日志保留。
- 日志：`_build/regen.log`（gitignored），CI artifact 保留 7 天。

### 3.4 数据检查器 `tools/check_artifact.py` 语法契约

解析器只接受两类记录行（同一行内不得有其它字段）：

| 形态 | 样例 | 来源 |
|------|------|------|
| raw | `  { adcode: "500233000000", name: "忠县", level: Area },` | `gen_adcodes.py` 当前输出 |
| formatted | `  { adcode: "500233000000", name: "忠县", level: Area, },` | `moon fmt` 输出 |

更新点：`tools/check_artifact.py:60-64` 的 `ENTRY_RE` 末段允许 `level` 后可选逗号。**六项自校与五项开关不变**：生成器 raw 自检 6/6；检查器 `--records` / `--fields` / `--levels` / `--order` / `--dup` 语义不变。

**Post-update 正向**：raw 与 formatted 两份 `data/adcodes.mbt` 副本都必须 `check_artifact.py --records --fields --levels --order --dup` exit 0。

**Post-update T2 负向**：

```text
  { adcode: "500233000000", name: "忠县" },
```

缺少 `level` → exit 2。字段不一致（如 adcode 改为 `500233000001`）→ `--fields` exit 1。预更新 formatted exit 2 只是当前缺口证据（F-08/U-06），不得当作 post-update T2 样本。

解析/IO 错误退出 2；字段不一致退出 1。输出首个失败行号与原文。

### 3.5 覆盖映射与 `tools/check_coverage.py`

**权威文档标题逐字**：`moon_cpca 上游用例覆盖映射 v1`。路径：`docs/moon_cpca-upstream-coverage.md`。版本：`v1`。

表结构：

| 序号 | 来源 | 输入 | 上游期望 8 字段 | moonbit_case_id | 状态 |
|------|------|------|------------------|------------------|------|

行数契约：14 行 = 11 条 `test_transform`（含整型 `32323` 类型层 N/A）+ 2 条 `test_umap` + 1 条 `pos_sensitive=false` 契约。状态枚举仅 `精确` / `类型层 N/A`；所有字符串输入状态为 `精确`。

**第 14 行固定值**：

| 序号 | 来源 | 输入 | 上游期望 8 字段 | moonbit_case_id | 状态 |
|------|------|------|------------------|------------------|------|
| 14 | pos_sensitive=false 契约 | 11 条 test_transform 输入 × pos_sensitive=false/缺省 | 无 pos 列（不适用） | `engine/location_fields_wbtest.mbt:location_pos_default_minus_one` | 类型层 N/A |

**`moonbit_case_id` 稳定语法**：

| 来源 | 形态 | 示例 |
|------|------|------|
| golden 行 | `golden:<exact input>` | `golden:天津市` |
| wbtest 行 | `engine/<file>.mbt:<test name>` | `engine/location_fields_wbtest.mbt:location_pos_fields_int_and_minus_one` |
| 整型 N/A 行 | `golden:<exact input>`，状态 `类型层 N/A` | `golden:32323` |
| pos_sensitive=false 契约 | wbtest ID | `engine/location_fields_wbtest.mbt:location_pos_default_minus_one` |

`check_coverage.py` 只解析上述两类前缀：`golden:` 与 `engine/`；未知前缀、未知文件名、未知 test name 均 exit 1，并在 stdout 打印行号与原始 ID。不得静默跳过。

`tools/check_coverage.py` CLI：

```bash
python tools/check_coverage.py --doc docs/moon_cpca-upstream-coverage.md
```

断言：

1. 表格数据行 = 14。
2. 状态 ∈ {`精确`，`类型层 N/A`}。
3. 每个 `moonbit_case_id` 按 §3.5 语法解析：`golden:<input>` 在 `testdata/golden.jsonl` 中存在；`engine/<file>.mbt:<test name>` 在该文件中存在 `test "<test name>"` 块。
4. 未知前缀/未知文件/未知 test name → exit 1，输出行号 + 原始 ID；不得跳过。
5. golden 覆盖 10 条字符串 `test_transform` 输入 + 2 条 umap 输入。
6. `test_umap` 第 2 条（`吉林省朝阳区不知道店` + `{"朝阳区":"110105"}`）有对应 case。

8. 第 14 行的 `输入`、`上游期望 8 字段`、`状态` 必须非空且逐字等于 §3.5 固定值：`11 条 test_transform 输入 × pos_sensitive=false/缺省`、`无 pos 列（不适用）`、`类型层 N/A`。

失败：exit 1，stdout 列出缺失/非法行的序号与 `moonbit_case_id`；不得静默跳过。示例合法 wbtest ID：`engine/location_fields_wbtest.mbt:location_pos_default_minus_one`。

### 3.7 CI 契约（四 job）

| job | required | 命令 | 成功判据 | 超时 |
|-----|----------|------|----------|------|
| `native` | 是 | `moon check --target native`；`moon test --target native --no-render` | 退出 0；出现 `Total tests: 39` 或更多 | 20 min |

`quality-gates` 七个具名步骤（FR-09）：

1. `moon fmt --check`
2. `moon check --target native`
3. `python tools/check_golden.py`
4. `python tools/check_deps.py`
5. `python tools/check_artifact.py --records --fields --levels --order --dup`
6. `python tools/test_gen_adcodes.py`
7. `python tools/regen.py` 后 `git diff --exit-code`

`wasm-gc` 若 runner 缺 loader：job 失败并阻断发布；不得 `continue-on-error`、不得登记 unresolved。`js` 可 `continue-on-error: true`，但必须有一个 `if: always()` 的 writer step 写 `_build/js_status.txt`（`green` 或 `unresolved: <reason>`），并 `actions/upload-artifact@v4`（name `js-status`，path `_build/js_status.txt`，retention 7 天）；README 同步该状态。`quality-gates` 的单次运行墙钟 ≤ 10 min（A-21），job timeout 20 min 仅作上限。

## 6. 批次完成定义（V1）

**Batch 0（gate 批）** = B0-00 基线 + B0-01～B0-06 gate 实现与验证；只允许 gate 所需的前置变更（快照/依赖/gitignore、checker、coverage doc/tool、格式迁移），不得进入功能实现。Batch 0 通过后 spec re-freeze；Batch 0 通过前不得开始 feature batch。

- **B0-00 基线**：记录 `moon version`、`git rev-parse HEAD`，运行全部现有命令（native check/test、fmt、check_artifact、check_golden、check_deps、publish dry-run、wasm-gc test、js test），记录红/绿与首个失败；不改代码。
- **B0-01 输入**：提交 8 文件 vendored 快照（含 `cpca/resources/__init__.py`）、`requirements-dev.txt`（pandas/pyahocorasick/setuptools）、`.gitignore` 缓存/生成残留条目。
- **B0-02**：`tools/regen.py` + wrapper 级网络 guard。
- **B0-03**：`check_artifact.py` 解析器更新（raw + formatted）。
- **B0-04**：`docs/moon_cpca-upstream-coverage.md`（14 行）+ `check_coverage.py` + `location_pos_default_minus_one` wbtest。
- **B0-05**：全项目 `moon fmt` 迁移（仅格式化，无语义编辑）+ DR-01 wrapper。
- **B0-06**：B0-01～B0-05 的 T1/T2 + spec re-freeze。

**Batch 1（rename/manifest）**：`moon.mod` + `moon.pkg` + README/scripts 改名；执行 post-rename `moon publish --dry-run` T1（202 + `Dry run completed successfully`）。
**Batch 2（CI workflow）**：四 job 工作流 + 首次完整运行（native/wasm-gc/quality/js）。

Batch 0 集成验证命令（不依赖 rename/CI）：

`git status --short` 必须为空；`moon publish --dry-run` 与四-job CI 不在 Batch 0（分别在 Batch 1/2）。

- 每个批次后插入**一次且仅一次**「整变更集成验证」，由独立集成验证者执行，不与其他 worker 并行。
